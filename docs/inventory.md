## 2. Discord facts the service rests on

| Fact                                                | What the docs say (16 October 2026)                                                                                                                                                                  | Consequence                                                                                                                                  | State                                                                 |
| --------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| The guild in the bot authorization's token response | OAuth2: with the bot scope and a code grant, the token response "also" carries the guild the bot was added to; the redirect's `guild_id` "should only be used as a hint".                            | The callback reads the guild from the token response.                                                                                        | confirmed in the docs; to see on the development application (DC-103) |
| Which removal signals fire                          | Webhook events: `APPLICATION_DEAUTHORIZED` carries only `user` and fires "when the app is deauthorized by a user"; no event is documented for a bot removed from a server.                           | Removal by 403/404 on use, the daily reconciliation, and `GUILD_DELETE` from Phase 2; `APPLICATION_DEAUTHORIZED` is never mapped to a guild. | confirmed                                                             |
| Webhook events' retries                             | Retried with exponential backoff for up to ten minutes; a 204 within three seconds; sending stops, by email, when the app fails too often.                                                           | Persist, then 204; dead-letter a failing handler.                                                                                            | confirmed                                                             |
| Interaction responses and channel permissions       | Neither the permissions page nor _Receiving and responding_ says that responses or follow-ups bypass channel permissions; `app_permissions` is "the permissions the app has in the source location". | The service reads `app_permissions` on every interaction and refuses up front.                                                               | open: to test on the development application (DC-102)                 |
| USE_APPLICATION_COMMANDS                            | The permissions table: "Allows members to use application commands"; nothing says the app needs it.                                                                                                  | Not asked for: 309237763136 (`src/permissions.ts`).                                                                                          | decided from the docs; to confirm on the development application      |
| Files per message                                   | Neither the message resource nor _Uploading files_ states a count; each file within the upload limit (20 MiB by default), a request at most 25 MiB.                                                  | The renderer bounds each file and the request's total.                                                                                       | confirmed (no count to keep)                                          |
| Autocomplete deadline                               | No autocomplete-specific deadline; the initial response within three seconds applies.                                                                                                                | Autocomplete answers from the cached allowance list, never a network call.                                                                   | confirmed                                                             |
| Interaction tokens                                  | Valid fifteen minutes; a deferral's ephemeral flag is kept, the follow-ups' ignored after a defer.                                                                                                   | The 14-minute switch to the bot token; delete `@original` and follow up ephemerally.                                                         | confirmed                                                             |
| Verification's minimum server count                 | _Enabling discovery_ names no server count; the criteria are in the portal's _App Verification_ checklist.                                                                                           | Read the portal with the user (DC-505).                                                                                                      | open                                                                  |

## 3. What Phase 1 rests on (16 October 2026)

| Fact                                                     | Where Discord says it                                                                             | Consequence in the code                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| -------------------------------------------------------- | ------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A thread started from a message takes the message's id   | _Channel resource_, Start Thread from Message: the created thread's id is the source message's id | A first `/ask` in a channel is keyed on its `@original` message id; the thread later started from that message has the same key (`threadIdOf`, `sessionUidOf`), and the session uid holds. The delivery target names the thread only once it exists: the first `PUT` maps the channel's message, and once the whole answer is shown and its thread started the session is `PUT` again with `threadId` (`HttpAgentClient.bindSession`, agent-runtimes 1.5.51); no thread (a private `/ask`, a missing permission, a failed start) keeps the first mapping. |
| A deferral's ephemeral state is kept                     | _Receiving and responding_                                                                        | The ingress decides it (a private `/ask`, an unlinked person, every `/datalayer` command); a public deferral that must turn private is deleted and followed up ephemerally (`Worker#privately`).                                                                                                                                                                                                                                                                                                                                                          |
| Interaction tokens last 15 minutes                       | _Receiving and responding_                                                                        | The worker switches to bot messages at 14 minutes or on a 404, and never reuses the token (`TOKEN_SWITCH_MS`, `DiscordError.tokenGone`).                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `GET /users/@me/guilds` pages 200 at a time with `after` | _User resource_                                                                                   | The reconciliation pages until a short page (`removal.ts`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Unknown Guild is JSON error 10004                        | _Opcodes and status codes_                                                                        | Only that code removes a server on use; Missing Access (50001) is a channel permission, never a removal.                                                                                                                                                                                                                                                                                                                                                                                                                                                  |

The provenance of a turn is sent on the turn itself from agent-runtimes
1.5.49 (`HostShape.provenanceOf`); `contracts.json` carries Discord's forms
(`discord`, `external_turn.optional_request.provenance`, `admin`), read by
`test/contracts.test.ts` here, by ai-agents' `test_app_hosts` and by
agent-runtimes' `test_app_host_sessions`.
